# Ядро — сайт подбора косметики по бюджету

Веб-версия (вместо Android). Backend на Python (FastAPI + SQLite),
фронтенд — обычный HTML/CSS/JS без сборки, адаптирован под телефоны.
ИИ — локальная модель через LM Studio или облачный Anthropic Claude API.

## Запуск

```bash
cd backend
python -m pip install -r requirements.txt
copy .env.example .env
python -m uvicorn app.main:app --reload --port 8010
```

Открыть http://localhost:8010 — фронтенд отдаётся тем же сервером.
(порт 8010, потому что 8000 на машине занят зависшим процессом;
после перезагрузки можно вернуть 8000)

## Аккаунты и авторизация

Вход обязателен: без него API отвечает 401, а фронтенд отправляет на
`login.html`. На одной странице и вход, и регистрация.

Как устроено (`services/auth.py`, `routers/auth.py`):

* **Пароли не хранятся.** В базе лежит только PBKDF2-HMAC-SHA256,
  200 000 итераций, у каждого пользователя своя соль. Сделано на стандартной
  библиотеке — ставить bcrypt или passlib не нужно.
* **Сессия** — случайный токен в таблице `sessions`, отдаётся браузеру в
  **httpOnly-куке**: из JavaScript она не видна, поэтому украсть её со
  страницы нельзя. Срок жизни 30 дней, при выходе запись удаляется.
* **Профиль принадлежит аккаунту.** У таблицы `profiles` появилась колонка
  `user_id`, а каждый профильный маршрут проходит через
  `require_profile_access`: чужой профиль отдаёт 403, даже если знать его id.
* При входе с неверным паролем и с несуществующей почтой ответ **одинаковый** —
  иначе по разнице сообщений можно было бы перебирать существующие аккаунты.

Проверено: регистрация, повторная почта (409), валидация почты и длины пароля,
вход/выход, истечение сессии, и главное — второй пользователь получает 403
на план и избранное первого.

Профили, созданные до появления авторизации, остались без владельца и теперь
недоступны — это ожидаемо, их можно удалить из `profiles`.

## Нейросеть

По умолчанию работает **локальная модель через LM Studio** — бесплатно,
офлайн, без ключей. Нужно только запустить LM Studio, загрузить модель
и включить сервер на порту 1234.

Настройки в `.env` (`AI_PROVIDER=local`):

```
LOCAL_AI_URL=http://localhost:1234/api/v1/chat
LOCAL_AI_MODEL=qwen/qwen3-4b-thinking-2507
LOCAL_AI_TIMEOUT=180
```

Проверить связь: `GET /api/meta/ai-status` или просто открыть «Профиль» —
там горит индикатор с названием модели.

Особенности эндпоинта LM Studio (`/api/v1/chat`), выяснены на практике:

* принимает `model`, `system_prompt`, `input`, `temperature`;
* native API использует **`max_output_tokens`**; для текстовых ответов задан лимит 2048 токенов;
* в приложении текстовые запросы отправляются без сохранения истории на сервере (`store=false`): массив сообщений не передаётся (только части
  контента text/image), поэтому историю переписки сворачиваем в текст запроса,
  беря последние 6 реплик под контекст 8k;
* ответ приходит массивом `output`, где **рассуждения модели
  (`type="reasoning"`) лежат отдельно от ответа (`type="message"`)** —
  пользователю показываем только второе;
* thinking-модель отвечает 10-20 секунд, поэтому в интерфейсе живой
  индикатор со счётчиком секунд, а таймаут запроса — 180 с.

Переключиться на облачный Claude: `AI_PROVIDER=anthropic` + `ANTHROPIC_API_KEY`.
Код сценариев общий, меняется только провайдер в `services/ai.py`.

Если модель не запущена, сайт продолжает работать полностью (квиз, бюджет,
план, каталог, цены, календарь) — просто вместо ответов ИИ показывается
понятное сообщение.

## Структура

```
backend/app/
  main.py            — FastAPI приложение, роуты, раздача фронтенда
  database.py        — SQLite, схема
  seed_data.py        — стартовый каталог (реальные бренды/составы, референсные цены)
  schemas.py          — pydantic-модели запросов
  routers/            — auth, profile, products, plan, calendar, chat, favorites, meta
  services/
    auth.py            — пароли, сессии, проверка владельца профиля
    matching.py       — правило-ориентированный подбор (тип кожи + бюджет + состав)
    ai.py              — нейросеть: локальная (LM Studio) или облачный Claude
    marketplaces.py    — адаптеры к площадкам (реализован Wildberries)
    feeds.py           — импорт цен из YML-фидов партнёрских программ
    scraper.py         — архитектура парсинга цен (см. ниже, статус: не подключено к живым магазинам)
frontend/
  login.html           — вход и регистрация
  index/quiz/budget/plan/catalog/product/calendar/chat .html
  css/style.css        — дизайн-система: токены, скругления, свечения, скроллбары
  js/api.js            — запросы, профиль (localStorage), иконки, избранное
  js/dnd.js            — перетаскивание на pointer-событиях (мышь + тач)
```

## Как это работает

1. Квиз (`quiz.html`) → **несколько типов кожи одновременно** (жирная +
   чувствительная — обычное сочетание) и проблемы, затем бюджет
   (`budget.html`) → `POST /api/profile` создаёт профиль и сразу строит план.
2. Подбор (`services/matching.py`) — объяснимый скоринг, не чёрный ящик:
   совпадение по типу кожи (×3), по проблемам (×2.5), популярность,
   штраф за цену. Отдельно: **если выбрана чувствительная кожа, продукты
   с ретинолом и кислотами получают сильный штраф** — поэтому для
   «жирная + чувствительная» движок берёт мягкую пенку вместо LHA-геля
   и не ставит в план кислотный тоник.
3. `plan.html` — план по шагам с бейджами («по составу», «выгодная цена»,
   «мягкая формула», «добавлено вручную»), шкала бюджета с перерасходом,
   и панель **избранного справа**: средство можно перетащить в план
   (или добавить кнопкой «+»), а шаги внутри плана — менять местами
   перетаскиванием за точки слева. Порядок сохраняется на сервере.
4. `catalog.html` — поиск/фильтры/сравнение цен, сердечко = в избранное.
5. `product.html` — состав, цены по магазинам, кнопка «Спросить ИИ»
   → `/api/products/{id}/ai-advice` (реальный вызов модели с контекстом
   текущего плана), плюс добавление в утренний/вечерний план.
6. `calendar.html` — чек-лист утро/вечер по дням, прогресс выполнения.
7. `chat.html` — свободный чат с контекстом профиля и плана.

Перетаскивание (`js/dnd.js`) написано на pointer-событиях, поэтому
работает и мышью, и пальцем на телефоне (нативный HTML5 drag-and-drop
на мобильных не работает).

## Профиль

`profile.html` — ответы опросника, бюджет и статистика. Опросник можно
пройти заново (`quiz.html?edit=1` подставляет прошлые ответы), либо
изменить только бюджет. В обоих случаях уходит `PUT /api/profile/{id}`:
план пересобирается, а **избранное, отметки в календаре и переписка
с ИИ сохраняются** — обнуляется только устаревший разбор кожи.


### Панель владельца в профиле

Обзор кожи, бюджет, ссылки на план и календарь, обновление опросника и выход доступны всем пользователям. Блок со статистикой профиля и состоянием ИИ показан только аккаунту, ID которого задан в `PROFILE_OWNER_ID` в локальном `backend/.env`. ID берётся из поля `users.id` базы данных. При пустой настройке панель скрыта у всех. Сервер проверяет ID вошедшего пользователя, а не адрес почты из localStorage. Файл `.env` и рабочая база не входят в Git.

## Как собирается план

Не «один продукт на категорию», а слоты «время суток × категория»
(`PLAN_SLOTS` в `matching.py`). Это важно: при подборе по категориям
победивший вечерний продукт (ночной крем, очищающее масло) оставлял
утро вообще без очищения и увлажнения. Теперь:

* очищение и увлажнение подбираются отдельно на утро и на вечер;
* продукт, уже купленный для другого блока, второй раз бюджет не тратит
  (и получает бонус к оценке — одним гелем логично умываться дважды в день);
* SPF попадает только в утро, эксфолиант и тоник — только в вечер;
* показываются шаги в порядке нанесения, а не в порядке подбора;
* при малом бюджете остаётся база, а активы отсекаются.

## Цены и доступность источников

Проверено вживую (сентябрь 2026). Важно: **robots.txt разрешает у всех**
проверенных площадок — упирается всё в защиту от ботов, а её обходить нельзя.

| Источник | Сеть | Ответ | Вывод |
|---|---|---|---|
| Wildberries (сайт) | ok | 200, но пустой SPA-каркас без цен | цен в HTML нет |
| Wildberries (search.wb.ru) | TCP таймаут из среды разработки | — | **проверь у себя**, адаптер готов |
| Ozon | TCP таймаут из среды разработки | — | проверь у себя; каталог JS + защита |
| Яндекс Маркет | ok | HTTP 403 | активная защита, только Partner API |
| Мегамаркет | TCP таймаут из среды разработки | — | проверь у себя; каталог JS |
| Золотое Яблоко | ok | страница «checking device» | защита, только партнёрский фид |
| Randewoo | — | капча даже на `/robots.txt` | не трогаем |
| Open Beauty Facts | ok | открытый API (ODbL) | состав, но не цены РФ |

TCP-таймауты выше — ограничение сети, в которой шла разработка, а не приговор
источнику. Прогони у себя:

```bash
python -m app.tools.check_sources
```

Инструмент показывает по каждой площадке: доступен ли хост, что говорит
robots.txt и что реально приходит в ответ. Ничего не пишет в базу.

### Сбор цен с площадки

Адаптеры — в `services/marketplaces.py`. Реализован Wildberries (их публичный
JSON-эндпоинт, тот же, которым пользуется их собственный фронтенд).
Ozon, Яндекс Маркет и Мегамаркет заведены как «неподдерживаемые» с указанием
причины и легального пути — чтобы причина была видна в отчёте, а не терялась.

```bash
python -m app.tools.update_prices --shop wildberries --dry-run   # посмотреть
python -m app.tools.update_prices --shop wildberries --limit 5   # 5 товаров
python -m app.tools.update_prices --reset                        # откатить к референсным
```

Если площадка отвечает капчей, 403 или таймаутом — обновление останавливается,
**цены в базе остаются прежними**, ничего не «дорисовывается».

### Откуда цена видно в интерфейсе

У каждой цены в базе есть `source`, и он подсвечивается:

* **голубая цена со свечением + метка LIVE** — `scraper`, собрано с магазина;
* **зелёная + метка ФИД** — `feed`, из партнёрского фида;
* обычная белая — `seed`, референсная цена по рынку.

Легенда есть на странице каталога. Сейчас в базе несколько цен помечены
`scraper`/`feed` **для проверки отображения** — сами цены при этом не менялись,
проставлена только метка источника. Сбросить: `update_prices --reset`.

### Легальный путь: товарные фиды (`services/feeds.py`)

Магазин сам публикует YML-фид, доступ к нему даёт CPA-сеть (Admitad,
ePN, Advcake). Никакого парсинга и обхода защит — данные отдают
специально, чтобы их использовали. Импорт:

```bash
python -m app.tools.import_feed --shop "Летуаль" --file letu.xml --dry-run
python -m app.tools.import_feed --shop "Летуаль" --file letu.xml
```

Сопоставление товаров намеренно строгое (совпадение бренда + минимум
двух значимых слов названия): лучше не сматчить и оставить старую цену,
чем подставить товару цену от другого продукта. `--dry-run` показывает,
что сматчилось, ничего не записывая.

### «Вежливый режим» парсера (`services/scraper.py`)

Для источников, которые сами разрешают обход. Правила зашиты в код,
нарушить их случайно нельзя:

1. **robots.txt проверяется перед каждым запросом** — запрещённый путь
   не уходит в сеть вообще;
2. **Crawl-delay соблюдается**, по умолчанию не чаще 1 запроса в секунду
   к домену;
3. **ответы кэшируются на диск на 24 часа** — повторный запрос не уходит;
4. **User-Agent честный**: имя бота, назначение и контакт, без маскировки
   под браузер;
5. **капча / device-check / 403 / 429 → домен помечается закрытым**
   до конца сессии, и обращения к нему прекращаются.

Модуль прекращает обращения при блокировке и не обходит её. HTTP 403, CAPTCHA
или сетевой timeout — технический результат конкретного обращения, а не
юридическое заключение о любом сборе открытых цен. Условия доступа, использования
страницы и права на базу данных проверяются отдельно. В старой проверке
Золотого Яблока модуль возвращал отказ:

```
ОТКАЗ: goldapple.ru: вместо контента отдана проверка на бота.
Обход не выполняется — используйте партнёрский фид (services/feeds.py)
```

Сейчас в `shop_prices` — референсные цены по рынку РФ (не выдуманные,
но и не live-данные), проставленные в `seed_data.py` вместе с реальными
названиями/брендами/активными веществами. Источник каждой цены виден
в колонке `source`: `seed` / `feed` / `scraper`.

## Дальнейшие шаги (не сделано в этой сессии)

- Получить реальный фид через CPA-сеть и прогнать `import_feed` —
  это заменит референсные цены на живые.
- Добавить предупреждение о несовместимости активных веществ в один
  день (ретинол + AHA/BHA, витамин C + ниацинамид) в `matching.py`.
- Дисклеймер про обращение к дерматологу при серьёзных проблемах кожи
  (сейчас это только в системном промпте ИИ, неплохо продублировать в UI).
- История цен по магазинам (график) — сейчас хранится только текущая цена.

## Подбор полного ухода с ИИ

На странице плана кнопка «Подобрать уход с ИИ» запрашивает у модели утреннюю и вечернюю схему из фактического каталога. Начальный план после опросника по-прежнему создаётся быстро обычным алгоритмом и подписан «Базовый подбор». План модели получает отдельную отметку только после применения.

- LM Studio: `/v1/chat/completions`, JSON Schema, 8192 токена на ответ вместе с рассуждениями Qwen Thinking. Текстовые консультации используют native `/api/v1/chat`. Таймаут берётся из `LOCAL_AI_TIMEOUT`.
- Модель выбирает ID товаров; сервер повторно проверяет наличие, допустимое время, базовые категории и стоимость уникальных покупок. Консервативный фильтр исключает ретиноиды из ежедневного автоматического подбора и отшелушивающие активы при чувствительной коже. Он опирается на ограниченные данные карточек и не является медицинской оценкой безопасности.
- Причины выбора на экране составляются из совпадений анкеты и известных полей карточки; неподтверждённые обещания из ответа модели не отображаются как факты. Резюме всего набора пишет модель.
- Предложение показывается до замены текущего плана, сохраняется после обновления страницы, действительно 30 минут и применяется отдельной кнопкой. Сбой модели, неверный ответ или нехватка бюджета не удаляют текущий уход.
- Если анкета, каталог, цены или план изменились, старое предложение применить нельзя. Избранное и отметки календаря при применении сохраняются. Ручная правка помечает план как изменённый пользователем.
- Итог — стоимость набора, а не точный месячный расход: данных о дозировках и сроке использования в базе нет. Нельзя обещать полностью персонализированную медицинскую рекомендацию по неполному списку активов.

API: `POST /api/plan/{profile_id}/ai-draft`, `GET /api/plan/{profile_id}/ai-draft`, `POST /api/plan/{profile_id}/ai-draft/{draft_id}/apply`, `DELETE /api/plan/{profile_id}/ai-draft/{draft_id}`. Все маршруты проверяют владельца профиля. Миграция SQLite создаёт `plan_drafts` и добавляет поля происхождения плана в `profiles`.

Документация интеграции: [LM Studio — structured output](https://lmstudio.ai/docs/developer/openai-compat/structured-output), [native chat](https://lmstudio.ai/docs/developer/rest/chat). Общие ориентиры для базовой схемы: [AAD — порядок ухода](https://www.aad.org/public/everyday-care/skin-care-basics/care/apply-skin-care-certain-order).
